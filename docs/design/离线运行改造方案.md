# 离线运行改造方案

日期：2026-10-09。状态：已实施，本地生产构建与Chromium离线验收通过；尚未发布本次改动，iOS／Android真机及实际安装待验证。操作方法见[项目入口](../../README.md)，结果见[离线验收记录](../reports/offline/README.md)。以下保留实施范围与验收设计。

## 目标与推荐

将现有网页改造成可安装的 PWA：玩家首次联网打开，完成完整资源缓存后，可以断网、关闭页面，再从浏览器或手机主屏幕进入游戏，继续旧局或开始新局。

推荐采用 `vite-plugin-pwa` 的 `generateSW` 策略，使用完整预缓存与提示式更新。当前游戏不依赖服务器计算，改造集中在资源交付、安装入口、更新与存档恢复。

本方案适用于“联网准备一次，此后离线玩”。如果要求设备从未联网也能首次安装，应另行提供内置资源的安装包；PWA 无法从没有下载过的资源中启动游戏。

## 当前代码依据

- React、TypeScript、Vite；当前五章版本的规则、地图生成与随机状态均在浏览器中处理。
- 图片从本项目的 `public/sprites/`、`public/portraits/`、`public/card-art/` 加载，路径已经使用 `import.meta.env.BASE_URL`。
- 操作音效通过 Web Audio 现场生成，没有外部音频下载；未发现远程字体或游戏运行所需的网络接口。
- `public/` 当前有172个文件，合计3,217,183字节，约3.2MB；现存构建目录约4MB，最终包大小须以实施时重新构建为准。
- 存档由 `src/game/storage.ts` 写入 `localStorage`，当前版本为3，沿用 `digimon-journey-v1` 键，已有旧档迁移和 JSON 导出。
- GitHub Pages 部署配置已有 `/digimon-card-roguelike/` 构建路径；尚无 PWA 清单与 Service Worker。

## 玩家体验

1. 首次联网进入后，可以正常游玩，同时后台准备离线资源。
2. 首页或设置显示“正在准备离线资源”；完整缓存安装成功后才显示“已可离线游玩”。不使用假的百分比。
3. 准备失败时显示“离线资源尚未准备完成，联网后重试”；首次下载中途断网不能宣称已完成。
4. 支持添加到主屏幕，以独立窗口打开。Android 在浏览器支持时提供安装按钮；iPhone 提供 Safari“分享→添加到主屏幕”的说明。
5. 断网状态不会限制开局、出牌、奖励、进化、图鉴、保存和读取。
6. 联网发现新版后显示“新版本已准备好”，提供“稍后”和“保存并更新”。战斗与动画进行期间延后更新操作。

离线可用与添加到主屏幕是两件事：完成缓存后，普通浏览器页面也应能离线重新打开。

## 改造设计

### 1. 安装与部署

- 在 `vite.config.ts` 接入兼容现有 Vite 6 与 Node 22 发布环境的 `vite-plugin-pwa`，实施时核对依赖兼容范围并锁定版本。
- 配置应用名称“数码旅途”、独立窗口显示、主题色与背景色；以竖屏为主要体验。
- 提供192和512像素 PNG 图标、maskable 图标，以及 Apple touch icon；优先复用现有标识。
- Manifest 的应用标识、入口和作用范围，与 Service Worker 路径均按构建 base 处理。正式站点限制在 `/digimon-card-roguelike/`，避免控制同域其他项目。
- 正式离线入口使用 HTTPS，可继续使用现有 GitHub Pages。电脑本地 localhost 可用于验证；手机访问普通 `http://局域网IP:5177` 不能作为标准 Service Worker 离线安装入口。
- 默认不在日常开发服务器注册 Service Worker；通过生产构建预览、专用测试地址及正式 HTTPS 地址验证。

### 2. 完整资源缓存

目前资源规模小，直接缓存完整游戏，比只缓存已见过的图片更适合。玩家离线首次到达新敌人、形态或图鉴页时，资源仍然齐全。

| 内容 | 缓存方案 |
| --- | --- |
| 页面、JS、CSS与拆分代码块 | 构建时生成完整预缓存列表 |
| 所有精灵静态图和动画表 | 全量预缓存 |
| 所有立绘、通用卡面 | 全量预缓存 |
| 安装图标、favicon、素材来源声明 | 全量预缓存 |
| 游戏配置 | 已随JS构建，随应用版本更新 |
| 存档 | 继续由页面写入本地存储，独立于资源缓存 |

- 显式配置图片、SVG、JSON和TXT等缓存范围，同时保留HTML、JS和CSS，不能只依赖插件默认模式。
- 缓存从正式构建输出生成；原始素材包、设计文档、开发夹具及测试存档不进入离线包。
- 页面导航回退到项目内已缓存的 `index.html`；图像等资源请求不能误回退成HTML。
- 使用文件内容修订标识更新未带哈希文件名的图片，避免新代码配旧卡面。
- 构建检查必须确认所有运行时必需资源都进入清单，且没有文件因单文件大小限制被跳过。
- 设置中使用简单状态与可选空间估算；`navigator.onLine` 仅辅助显示连接状态，不作为缓存完整性的证据。

### 3. 游戏更新

采用提示式更新：新版本下载完整并安装成功后等待切换，旧版本可以继续使用。

- 联网打开、回到前台或主动检查时，适度检查更新，不持续后台轮询。
- 提示出现后可以稍后处理；出牌动画、敌人行动序列进行时不激活新版或强制刷新。
- 首轮采用更简单的约束：整个战斗阶段延后“保存并更新”，结束战斗后允许执行。
- 执行更新前，调用现有存档写入函数确认成功；保存失败时保留当前页面，并提供备份入口。
- 新版就绪后切换并重载，从现有存档及迁移逻辑恢复。
- 更新下载失败时仍保留当前可用版本；在新版本激活阶段清理本项目过时资源缓存，不清除玩家存档或同域其他应用缓存。
- 多窗口场景单独验证：避免一个窗口切换后另一个窗口静默丢失操作；首轮不新增多窗口同步游玩能力。

### 4. 存档与恢复

离线能力不要求迁移到 IndexedDB。当前JSON存档继续使用 `localStorage`，保留v3迁移与读取错误处理；也不因为加入PWA而单独升级游戏存档版本。

建议在交付中补齐“导入存档”，与现有导出组成完整恢复流程：

- 选择本地JSON后，先用现有 `parseSave` 验证兼容性，限制文件大小，验证失败不覆盖当前存档。
- 预览搭档、形态、进度及图鉴概况，明确说明导入将替换当前记录。
- 确认时先备份当前记录，再写入新存档；取消、解析失败或保存失败均保留原记录。
- 导入完成后重新初始化游戏，避免旧动画队列或旧状态继续覆盖新记录。
- 可在支持的平台请求持久存储，降低自动清理概率；申请被拒绝也能正常游玩，不承诺永不丢档。

从局域网地址切换到正式HTTPS站点，会进入另一套浏览器存储。浏览器与主屏幕应用间的存档连续性也需真机验证，不能假设始终共享。提供导出／导入是可靠的转移途径。

### 5. 修改位置

| 文件／位置 | 计划改动 |
| --- | --- |
| `package.json`、锁文件 | 增加PWA构建依赖及必要验证工具 |
| `vite.config.ts` | 生成Manifest与Service Worker，设置完整预缓存、base与更新模式 |
| `index.html`、`public/` | 安装元信息、桌面图标与Apple图标 |
| 新增 `src/pwa/` 模块 | 注册、离线状态、更新检查与切换封装 |
| `src/App.tsx` | 接入离线提示，并将更新与战斗状态、存档结果关联 |
| `src/components/SettingsView.tsx` | 安装说明、离线状态、版本更新、导入存档入口 |
| `src/game/storage.ts`及必要的存档界面 | 复用校验与迁移，提供安全导入／恢复 |
| `tests/` | 生产构建缓存覆盖、离线启动、更新与存档回归 |
| README、当前项目说明 | 更新离线使用方法、正式入口及限制 |

## 实施顺序

1. **离线核心**：完整预缓存、项目路径范围、离线重新启动、已有存档恢复。
2. **安装与提示**：应用图标、主屏幕安装、真实离线准备状态、提示式更新。
3. **恢复与交付验收**：补齐存档导入；验证发布升级、旧档迁移、iPhone与Android实际离线启动。

前三部分建议一起作为首轮交付。后续仅在资源体积明显增长时，再评估分章下载或按需资源包。

## 验收条件

- 首次联网完成准备后，启用飞行模式并关闭应用，再打开仍进入完整游戏。
- 在离线状态下能够继续旧局、开始新局，并正常经过战斗、奖励、宝箱、商店、事件、进化和存档。
- 准备离线资源后，无需在线浏览所有角色，离线首次查看任意形态与敌人仍有图片和动画。
- 离线刷新、重新打开后，手牌、牌堆、敌方行动进度、随机状态、扫描与路线资料按现有规则恢复。
- 发布新版后，旧版仍可离线启动；更新下载中断不破坏旧版；完整下载后提示更新，战斗中不强制切换。
- 更新后的存档读取正常，包含现有v3与支持迁移的旧版；导入失败与取消不覆盖存档。
- 使用生产构建验证缓存清单与GitHub Pages子路径；开发夹具、测试存档不混入正式缓存。
- 验证iOS Safari／主屏幕应用、Android Chrome／安装应用和桌面Chrome；自动化浏览器检查不能代替手机飞行模式验收。
- 清除浏览器站点数据后，需要重新联网准备并恢复备份。第一次访问前从未下载过游戏的设备不能离线首次启动。
